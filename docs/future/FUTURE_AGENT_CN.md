**为什么单独成文**

Agent 能力是**横切关注点**：它复用 M1 的鉴权、依赖 M3 的候选人数据、在 M4 / M7 上开展示入口，却**不天然属于 M1–M7 中任何一格**。单独成文才能逐条取舍，避免把范围变更悄悄塞进别人的模块。

## 1. 定位与红线（任何条目被采纳前都必须成立）

| # | 红线 |
| --- | --- |
| R1 | **只读**：不写入选票相关表（`ballots`、`ballot_choices`、`vote_participation`），也读不到「谁投了谁」 |
| R2 | **不推荐**：不回答「投给谁 / 谁更好 / 谁会赢」，不对候选人排序 |
| R3 | **必须引用**：每条结论附出处；无出处即声明「材料中未提及」 |
| R4 | **准入**：登录（M1）＋ 该选举资格校验（M2 / M4）通过才可用；最终鉴权在后端 |
| R5 | **隐私**：选民提问可能暴露投票倾向，`agent_run` 默认匿名化，不保存可关联到个人的问题原文 |
| R6 | **降级**：模型不可用时返回材料原文或明确提示，不得 500、不得编造 |

## 3. 依赖与前置条件

1. **数据前置**：FWA-01 是 FWA-02 / 03 / 05 的前置。若只有 v0.1 的「候选人简介」短字段（每候选人一段话），检索层没有意义——**先有材料，才谈 RAG**。
2. **接口复用**：认证复用 M1（FR-05 / FR-06）；准入复用 M2 / M4 的资格判定（FR-07）。
3. **成本与密钥**：LLM / Embedding 的密钥只允许存后端环境变量，禁止写入仓库或前端；需先明确由谁提供、如何计费与限流。
4. **隐私评审**：R5 与 AC-07 匿名性同源，采纳时需后端 3 联署评审。
5. **架构决策**：采纳任一条目前，先写 ADR 放入 `docs/architecture/`。

## 4. 明确不在本提案内

- 任何写入票务数据的操作、自动判定选票有效性、「Agent 代替用户投票」；
- 对 MVP（M1–M7）范围、时间表、验收标准的任何改动；
- 使用真实选民数据；对候选人作推荐或排名。

## 5. 若未来获准，建议的采纳顺序

1. `FWA-01` 候选人材料结构化（纯数据，无 AI 依赖，先落地不冒险）
2. `FWA-08` 评测框架（先有尺子，再动手做模型能力）
3. `FWA-02 + FWA-03 + FWA-04` 最小可用问答（检索 + 生成 + 护栏）
4. `FWA-07` 审计与反馈
5. `FWA-05 / FWA-06 / FWA-09` 体验扩展
6. `FWA-10` 研究性加分项
